## Що треба виправити в тексті .docx

Ці розбіжності знайдено при звірці тексту з кодом і даними — інакше нові рисунки
суперечитимуть тексту:

1. **Архітектура регресора.** У тексті «12–64–32–6», у коді
   (`src/pointsx/regression/model.py`) — **28**→64→32→6: 28 вхідних ознак.
2. **Синтетичний набір.** У тексті «1500 3D-рендерів», фактично навчання йшло на
   **3 395** тіл (`notebooks/05_train_regressor_colab.ipynb`, вивід комірки 13:
   `features: (3395, 28)`).
3. **Таблиця 3.1 і загальний MAE.** У тексті «MAE 3,29 см, 205 спостережень,
   обхват біцепса 3,46 см» — це інший прогін. Канонічний (той, з якого зроблено всі
   рисунки й нову таблицю 3.1): **MAE 3,32 см, 206 спостережень, біцепс 3,92 см**.
   Текст §3.3.2 і висновки треба перерахувати з нього.
4. **§3.3.3 (точність підбору типорозміру).** Accuracy 97,1 %, Macro-F1 0,968,
   weighted kappa 0,982 не мають джерела: форма збору датасету фіксує **мірки**, а не
   розмір одягу, який людина носить, тобто еталонної мітки розміру не існує.
   Замість цього можна порахувати **узгодженість**: прогнати sizeEngine окремо на
   ручних мірках і на мірках з фото для тих самих 16 суб'єктів і показати частку
   точних збігів, збігів у межах ±1 розміру, weighted kappa та частку no-consensus.
   Це чесна метрика на реальних даних; підпис має звучати як «узгодженість
   рекомендації за фото з рекомендацією за ручними мірками», а не «accuracy».
5. **Рисунок 2.1 (архітектура регресора).** Регресор у продакшні вимкнений
   (`POINTSX_USE_REGRESSOR` не встановлено). Це варто зазначити в підписі: він
   поданий як досліджений варіант, який програв аналітичній моделі на реальних фото.

## Word-файл для передавання

`scripts/paper/build_docx.py` збирає всі рисунки й таблиці в один .docx, відкриваючи
файл роботи як шаблон — стилі (Normal = Times New Roman 14 пт, півтораінтервальний,
абзацний відступ 1,25 см; «Heading 1…3»; таблиці «Table Grid1») переносяться без змін,
тому блоки можна копіювати в основний документ без перевстановлення форматування.

```bash
python scripts/paper/build_docx.py --template "<шлях>/FitMeasureAI_КПІ.docx" \
    --out FitMeasureAI_рисунки_і_таблиці.docx
```

Потрібен `python-docx` (у системному Python, не у `.venv` — щоб не чіпати `uv.lock`).
Документ містить розділ «Позначення», де пояснено MAE, bias, RMSE, n, 95 % ДІ, IQR,
діаграму Бланда — Альтмана та mAP50-95.
